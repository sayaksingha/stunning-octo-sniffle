TCP Packet contents and their relevance to ASSP

Here's a list of TCP packet fields with considerations of how necessary they are in ASSP:

source port
Something similar is required. See discussion of addressibility.
dest port
Something similar is required. See discussion of addressibility.
sequence number
Essential. See discussion of sequencing.
acknowledgement number
Essential. See discussion of sequencing.
data offset
This is merely an encoding overhead.
FIN
Essential. Very rare (only once per connection) - replace with an option.
SYN
Essential. Very rare (only once per connection) - replace with an option.
RST
Essential but rare (never in a correct connection) - replace with an option.
PSH
Seems useful.
ACK
Not needed - all packets have valid ACK numbers.
URG
Should rarely occur in packets - replace with an option.
ECE - rfc 3168
Important. See discussion of ECN.
CWR - rfc 3168
Important. See discussion of ECN.
window
Something equivalent is required. See discussion of flow control.
checksum
Something equivalent is required.
urgent pointer
Should rarely occur - replace with an option.

Additionally, the following options may be present:

NOP - for padding
Not needed if we make options align themselves.
MSS - limit packet sizes
Useful. The application may group items into transactions. Identifying a maximum size allows the protocol to avoid IP fragmentation.
WSOPT - window scaling - rfc 1323
Avoid by making window large enough.
SACK permitted - enable sending SACK
Avoid by requiring SACK support.
SACK - selective acknowledgement
Something equivalent is required.
TSOPT - timestamp
Something equivalent is required. (RFC 1323) The main purpose of this field is to let the transmitter predict when an acknowledgement should arrive. Therefore its use allows accurate estimates of the RTT including any effects such as receiver application delays and deferred ack all of which should influence when the transmitter assumes packet loss.
CC - rfc 1644
See discussion of T/TCP.
CC.NEW - rfc 1644
See discussion of T/TCP.
CC.ECHO - rfc 1644
See discussion of T/TCP.
alternative checksum
Not required - but permit for experimental use.
MD5 signature - rfc 2385
Not necessary, but suitable for experimental purposes. Option only.
Reserved
Essential. Future extensions may need status which appears in every packet, which would be extremely wasteful to encode in an option (e.g. the proposed ECN nonce sum).

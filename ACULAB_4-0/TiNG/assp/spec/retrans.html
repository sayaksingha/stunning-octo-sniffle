Expected number of transmissions

Given a packet is lost with probability p, what is the expected number of packets required to receive a response to a command?

Suppose the expected number of packets required is N.

Let q = 1-p

When we send the command, if it is lost we have sent a packet and still need N to reach the target, so in this case we need N+1 packets with probability p. i.e (N + 1)p

If the command arrives and the response is lost, we again need a further N packets, but we have sent two, so in this case we need N+2 packets with probability qp. i.e. (N + 2)qp.

Finally, if neither the command nor the response are lost we need 2 packets with probability q*q. i.e. 2q*q

In total this gives: 

	N = (N + 1)p + (N + 2)qp + 2q*q
	N = Np + p + Nqp + 2qp + 2q*q
	N = N(p + qp) + p + 2qp + 2q*q
	N(1 - p - qp) = p + 2qp + 2q*q
	N(1 - (1 - q) - q(1 - q)) = (1 - q) + 2q(1 - q) + 2q*q
	N(1 - 1 + q - q + q*q) = 1 - q + 2q - 2q*q + 2q*q
	N(q*q) = 1 + q
	N = (1 + q) / (q*q)

Now suppose that three packets are required: command, response, ack.

Suppose the expected number of packets required is M.

If the command is delivered, the number of packets required to deliver the response is exactly as derived above, so it's q(N+1).

If the command is lost, we resend it and still have to send M more to finish, so this is p(M+1).

Note that this underestimates the transmissions in a real protocol since it assumes that packets are only re-transmitted when lost. In practice, a lost response is liable to cause re-transmission of the command because of a timeout waiting for the response, and simultaneous re-transmission of the response caused by timeout at the other end waiting for an acknowledgement. While a good choice of timeouts may reduce this effect, when adaptive timeouts are used it is very difficult to determine the number of extra packets sent, so we use the theoretical minimum, since actual protocols cannot be better than this.

This gives: 

	M = q(N + 1) + p(M + 1)
	M = qN + q + pM + p
	M(1 - p) = qN + q + p
	Mq = qN + q + p
	Mq = qN + q + (1 - q)
	Mq = qN + q + 1 - q
	Mq = qN + 1
	M = (qN + 1) / q
	M = (q(1 + q) / (q*q) + 1) / q
	M = ((1 + q) / q + 1) / q
	M = (1 + q) / (q*q) + 1 / q
	M = (1 + q) / (q*q) + q / (q*q)
	M = (1 + q + q) / (q*q)
	M = (1 + 2*q) / (q*q)

Let's see what difference the ack makes. It means we need to send an extra (M - N) packets. Can this be negative? 

	M - N = (1 + 2*q) / (q*q) - (1 + q) / (q*q)
	M - N = (1 + 2*q - (1 + q)) / (q*q)
	M - N = (1 + 2*q - 1 - q) / (q*q)
	M - N = q / q*q
	M - N = 1 / q

Since 0 <= q <= 1, this can never be negative, so acknowledgements always result in extra traffic. In particular, for a given q the extra traffic is:

q extra
1 1 (obviously - it's the ACK)
.999999 1.0000010000
.99999 1.0000100001
.9999 1.0001000100
.999 1.0010010010
.99 1.0101010101
.9 1.1111111111
.5 2.0000000000

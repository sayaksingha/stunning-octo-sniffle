API reference for an ASSP implementation

This is the reference manual for An ASSP implementation.

API functions

The API provides these functions:

int assp_init(void);
Initialise the ASSP implementation library. This must be the first function from this library that you call.
int assp_fini(void);
Undo initialisation of the ASSP implementation library. This must be the last function from this library that you call, with the exeption that after calling assp_fini() you may call assp_init() and start using the library again. It is not normally necessary to call assp_fini() unless you want to free any resources the library might be using in a long-running server when a configuration change indicates that the protocol is no longer needed.
PACKET *assp_txpacket(TCB *tcb, unsigned maxdlen);
Allocate space for a new packet for transmission. On return, the datastart field points to a buffer into which the data to be transmitted must be copied. The dataend field must be updated to point to the address after the last byte of data and is initialised to the maximum value it can be in this packet. The parameters are:
tcb
The TCB on which the packet will be sent.
maxdlen
The maximum number of octets of data that the packet might be required to hold.
U32 assp_rx_cid(PACKET *pkt);
Returns the CID value encoded in a received packet.
pkt
Points to the packet.
void assp_handle_rx(TCB *tcb, PACKET *pkt);
Causes the protocol to process a received packet.
tcb
The TCB for which the packet has been received.
pkt
Points to the packet.
int assp_connect(TCB *tcb, U32 cid);
Initiate a connection.
tcb
The TCB to use for the connection.
CID
The CID (connection ID) value to use.
int assp_txready(TCB *tcb);
Indicates that there is more data available for transmission.
tcb
The TCB to use for the connection.
int assp_abort(TCB *tcb, PACKET *txp);
Abruptly close a connection.
tcb
The TCB of the connection to be closed.
txp
The packet to use for closing the connection, which must have been allocated with assp_txpacket(). This packet does not normally carry data, and is not reported back through txack(). This parameter may be the null pointer, in which case no RST packet is sent. This is intended for handling the situation where the underlying connectivity is lost.
int assp_validate(TCB *tcb);
Ensure that there is network activity. If the TCB is not currently expecting a reply to some packet, provoke a reply by sending a packet (re-transmitted as necessary until there is a reply).
tcb
The TCB of the connection to be validated.
void assp_tcb_init(TCB *tcb, ASSP_CONN *cnx, TIMEQUEUE *tq, TCBPATH *tcbpath, struct assp_tcb_vtbl *vtbl);
Prepare a TCB for use.
tcb
The TCB to prepare.
cnx
An arbitrary parameter which the protocol will pass to your functions when it calls them.
tq
The TIMEQUEUE object to use for timeouts on this TCB.
tcbpath
The TCBPATH object to use for this TCB. A TCBPATH represents the underlying connection to the remote party.
vtbl
The table of your functions that the protocol invokes in response to various events. These functions are passed the cnx parameter when they are invoked. The table contains these functions:
int (*sof)(ASSP_CONN *cnx);
Called before any other function when a connection opens. For incoming connections, the return value indicates whether or not to accept the connection, with a non-zero value signifying acceptance. For outgoing connections, the return value is ignored.
void (*rx_peek)(ASSP_CONN *cnx, unsigned ofs, PACKET *pkt);
Called whenever new data is received. ofs is the number of packets missing between the next packet due to be delivered (with deliver()) and this one. The packet fields datastart and dataend point to the received data. ASSP retains ovnership of the packet passed into this call.
void (*deliver)(ASSP_CONN *cnx, PACKET *pkt);
Delivers received data. ASSP surrenders ownership of the packet when it calls this function, which must arrange for the packet to be freed whenever it is no longer required.
void (*eof)(ASSP_CONN *cnx);
Called after delivery of the last received packet on this connection when such a packet indicates EOF. No further data can be delivered after this function is called (neither via rx_peek() nor deliver()).
void (*stopped)(ASSP_CONN *cnx);
Called when the connection starts closing. From this point, no further data can be sent or received, and unacknowledged data may be lost.
void (*closed)(ASSP_CONN *cnx);
Called when the TCB is no longer required by ASSP.
PACKET *(*nexttx)(ASSP_CONN *cnx, int *flags);
Called when it is possible to send a new packet. This function must either return 0 to indicate that there is no data ready for transmission, or a packet containing the data to send. *flags must be set to any desired per-packet flags, the bitwise OR of any of these values:
ASSP_F_EOF
There is no further data to transmit. This can be specified even if the function returns 0. If a packet is returned, the logical end of file occurs after the data in the packet.
ASSP_F_ACKLESS
The returned packet is a reply to the remote party. The remote is responsible for soliciting re-transmissions if it does not arrive, so do not re-transmit if no response is received.
ASSP_F_FASTACK
The returned packet is time-sensitive and requires an instant acknowldgement so that it can be re-transmitted very quickly if no acknowldgement is received soon.
void (*txack)(ASSP_CONN *cnx, PACKET *txp, int acked);
Invoked when the fate of txp is known. If the packet has been acknowledged, then acked is non-zero: otherwise the packet may have been lost (e.g. the connection has been reset).
void assp_tcb_dtor(TCB *tcb);
Destroy a TCB. After destroying a TCB it becomes invalid and must not be passed into any function (except, of course, assp_tcb_init()).
tcb
The TCB to be destroyed.
